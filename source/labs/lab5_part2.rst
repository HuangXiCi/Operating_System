第二部分：页表与写时复制
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

第一部分已经完成物理内存分配及伙伴系统。本部分继续使用同一份 xv6 工程，
从进程的虚拟地址空间出发，观察页表映射，并实现写时复制
（Copy-on-Write，COW）机制。

普通 ``fork()`` 在创建子进程时复制父进程的用户内存。子进程随后若执行
``exec()``，这些刚复制的数据可能很快就被丢弃。COW 将复制推迟到实际写入时：
父子进程先共享物理页，某一方写入时再按需建立独立副本，同时保持数据隔离。

本部分关注页表、页面权限、写缺页和共享页生命周期。沿用第一部分的物理页分配、
回收接口；只补充共享页面所需的引用管理，不重复实现伙伴系统的拆分与合并。

2.2 观察页表与地址转换
--------------------------------------------------------------------------------

阅读三级页表
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

本实验使用 xv6 的 Sv39 页表和 4 KiB 页面。一个虚拟地址的低 39 位可分为：

.. list-table:: 虚拟地址字段
   :header-rows: 1
   :widths: 25 25 50

   * - 字段
     - 位范围
     - 作用
   * - ``VPN[2]``
     - ``38:30``
     - 索引最高一级页表。
   * - ``VPN[1]``
     - ``29:21``
     - 索引中间一级页表。
   * - ``VPN[0]``
     - ``20:12``
     - 索引最低一级页表。
   * - 页内偏移
     - ``11:0``
     - 定位页面内部的字节，转换前后保持不变。

有效地址范围仍须遵守 xv6 的 ``MAXVA`` 约束。阅读 ``walk()`` 时，注意循环如何逐级
取出索引，以及 ``alloc`` 参数何时允许分配中间页表。``walk()`` 返回页表项指针；
``walkaddr()`` 则检查用户映射并返回物理页起始地址。二者返回值的含义不同。

实现页表打印
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

在 ``kernel/vm.c`` 实现 ``void vmprint(pagetable_t pagetable)``，
并在 ``kernel/defs.h`` 中声明。打印根页表地址，再递归打印有效页表项；
每项至少包含索引、PTE 原值、物理地址及 ``R/W/X/U`` 权限。

有效项由 ``PTE_V`` 判断。在本实验的普通三级页表中，
``R/W/X`` 均为 0 的有效项指向下一级页表；叶子项指向被映射的物理页，
不能继续当作页表递归。可参考 ``freewalk()`` 的遍历方式，
但页表打印函数不得修改映射或释放内存。

参考输出的结构如下，实际地址以运行结果为准：

.. code-block:: text

   page table 0x0000000087f52000
    ..0: pte 0x0000000021fd3801 pa 0x0000000087f4e000 flags=----
    .. ..0: pte 0x0000000021fd3401 pa 0x0000000087f4d000 flags=----
    .. .. ..0: pte 0x0000000021fd3c1b pa 0x0000000087f4f000 flags=R-XU

在进程用户页表建立完成后的合适位置调用 ``vmprint()``，记录至少一个进程的页表。
应限制调试打印的触发范围，避免每次 ``exec()`` 都大量打印而干扰后续测试。

实现地址查询系统调用
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

增加用户接口：

.. code-block:: c
   :caption: user/user.h

   uint64 vmtranslate(uint64 va);

该接口只查询 **当前进程** 的用户地址映射：成功时返回完整物理地址；
地址越界、未映射或不允许用户访问时返回 ``0``。查询不得分配页面、
触发懒分配或改变原有权限。物理地址按下式得到：

.. code-block:: c

   pa = PTE2PA(*pte) + (va & (PGSIZE - 1));

按照前面实验的系统调用接入方式，选择未使用的系统调用号，
完成用户入口、内核分发表和处理函数。修改 ``user/usys.pl``，
不要直接修改生成的 ``user/usys.S``。

编写 ``user/vmtest.c``，查询全局变量、栈变量以及 ``0x40000000``
这一未映射地址。将程序加入 ``Makefile`` 的 ``UPROGS``。

.. admonition:: 必做：打印页表并验证地址转换
   :class: mytodo

   #. 提交 ``vmprint()``、``vmtranslate`` 系统调用及 ``vmtest`` 的实现。
   #. 记录页表输出，解释至少一条有效映射和对应权限。
   #. 打印全局变量、栈变量的 VA 与 PA，验证二者低 12 位一致。
   #. 验证未映射地址查询返回 ``0``，系统仍能正常运行。

用于核对地址的页表必须属于同一进程和同一运行阶段。
启动时打印的 ``init`` 页表，不能直接用来核对后续 ``vmtest`` 进程的物理地址。

.. admonition:: 小心：地址查询不能改变被观察的映射
   :class: mycaution

   查询时使用不分配中间页表的遍历方式，并检查 ``PTE_V`` 与
   ``PTE_U``。若查询本身触发懒分配，测试得到的物理地址就不再代表
   查询前的状态。返回完整物理地址时别漏掉页内偏移。

2.3 记录普通 fork 的行为
--------------------------------------------------------------------------------

在修改 ``uvmcopy()`` 之前，为 ``vmtest`` 增加父子进程对照测试。

将全局变量初始化为 ``100``、栈变量初始化为 ``200``；在 ``fork()`` 前打印父进程的
PID、变量值、VA 和 PA。子进程先打印相同信息，再将两变量修改为 ``999`` 和 ``888``，
打印修改后的结果并退出。父进程通过 ``wait()`` 等待子进程结束，再检查自己的变量。

使用 ``wait()`` 安排输出顺序即可，不要依赖固定延时来保证子进程先完成。

.. list-table:: 普通 fork 的预期现象
   :header-rows: 1
   :widths: 40 60

   * - 观察项目
     - 预期结果
   * - 同一变量的父子 VA
     - 相同，子进程继承父进程的虚拟地址布局。
   * - 同一变量的父子 PA
     - 不同；子进程写入前就已经有独立的物理页。
   * - 子进程修改后的父进程数据
     - 仍为 ``100`` 和 ``200``。

阅读 ``uvmcopy()``，将上述输出与 ``walk()``、``PTE2PA()``、
``kalloc()``、``memmove()``、``mappages()`` 对应起来：
它从哪里取得父进程的物理页，又如何给子进程建立映射？

2.4 实现写时复制
--------------------------------------------------------------------------------

本节应连通共享映射、引用计数、用户态写缺页以及 ``copyout()`` 四条路径。
仅让父子进程映射到同一物理页，尚不能保证写入隔离和正确回收。

共享映射与 COW 标记
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

修改 ``uvmcopy()``：为子进程建立页表，但不立即复制父进程的用户物理页。
对父进程中原本可写的页面，清除父子页表项中的 ``PTE_W``，
并设置一个软件使用的 ``PTE_COW`` 标记。可使用尚未占用的 RSW 位，例如：

.. code-block:: c
   :caption: kernel/riscv.h

   #define PTE_COW (1L << 8)

原本只读的代码页仍可共享，但不能因为 ``fork()`` 被标记为可恢复写权限的 COW 页。
已经带有 COW 标记的页面再次 ``fork()`` 时，应保留其标记和只读状态。
保持懒分配留下的未映射区域，不得为了 ``fork()`` 预先补齐所有页面。

建立子进程映射成功后，确保共享页的引用计数增加。
若中途失败，应撤销已建立的子进程映射并正确恢复引用数量；
不能将仍被父进程使用的物理页提前释放。父进程已修改的页表项
也必须保持可正常使用：可以回滚权限，或保留引用数为 1 的 COW 标记
并由写缺页路径正确处理。

共享页的引用管理
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

复用第一部分的物理页分配、回收接口，在其上维护每个物理页的共享引用。
本节只要求以下生命周期规则：

.. list-table:: 引用计数规则
   :header-rows: 1
   :widths: 42 58

   * - 操作
     - 引用管理要求
   * - 分配一个新物理页
     - 初始引用数为 ``1``。
   * - 新增一个共享映射
     - 对应物理页引用数加 ``1``。
   * - 删除映射、进程退出或 COW 替换旧页
     - 对应物理页引用数减 ``1``。
   * - 引用数减至 ``0``
     - 才能交给第一部分的分配器真正回收。

可设置增加、查询引用数的辅助接口，例如 ``kincref()``、``krefcnt()``；
回收入口须区分“移除一个引用”与“实际归还物理页”。
引用计数的读写须有适当的锁保护，并保证启动初始化、普通分配和失败清理仍然正确。

**保留第一部分已经实现的分配策略与元数据。**
若底层采用伙伴系统，只在最后一个引用消失时进入原有的回收路径；
不要用新的空闲链表实现覆盖第一部分的分配器，也不要重复编写拆分、合并算法。

.. admonition:: 小心：引用计数管理的是共享页的生命周期
   :class: mycaution

   COW 共享的是单个用户物理页。新增映射时增加引用，解除映射时减少引用，
   仅在计数变为 0 时才真正调用底层回收逻辑。初始化伙伴系统时加入的
   空闲页尚无引用，不能错误地走“减少引用”路径。多页块仍按申请时的
   阶数整体释放，不要把它拆成多个单页引用来回收。

用户态写缺页
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

用户程序写入不可写页面时产生 store page fault，``scause == 15``。
``stval`` 给出出错虚拟地址；先检查地址范围，再向下对齐到页边界，
查找并验证该页表项。

只有有效、允许用户访问且带有 COW 标记的页面，才能按 COW 处理。
可新增 ``cowfault()`` 等辅助函数，实现以下行为：

#. 分配新的物理页，将旧页内容复制到新页；
#. 将当前进程的页表项改为映射新页，设置 ``PTE_W`` 并清除 ``PTE_COW``；
#. 更新地址转换缓存，减少旧物理页的引用；
#. 返回用户态，重新执行引发缺页的写指令。

当旧页仅剩当前一个引用时，可以直接恢复写权限并清除 COW 标记，
省去分配和复制。这是可选优化；无论是否实现，真正的只读页都不能
因此变为可写。

当前源码已经由 ``usertrap()`` 将缺页交给 ``vmfault()``，
可在 ``vmfault()`` 中区分“尚未映射的懒分配页面”和“已经映射的 COW 页面”，
保留现有懒分配处理。读缺页 ``scause == 13`` 不能被当成 COW 写入来处理。

地址非法、写入真正的只读页或分配新页失败时，应终止出错进程，
不能让整个内核崩溃。处理成功后，不要将保存的 ``epc`` 加 ``4``：
本次必须重试原写指令，与前面实验处理 ``ecall`` 的返回位置不同。
还要保留栈保护页原有的 ``PTE_U`` 状态，不能在复制后让它对用户可访问。

内核向用户空间写入
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``read()`` 等系统调用可能通过 ``copyout()`` 将内核数据写入用户缓冲区。
``copyout()`` 根据用户页表取得物理地址后复制数据，
这一路径不会自动通过用户态 store page fault 处理 COW。

因此，应在 ``copyout()`` 的逐页写入循环中检查目标映射：
目标是 COW 页时，先解除共享，成功后使用 **更新后的物理地址** 写入；
目标是真正的只读页时仍然拒绝写入。跨页写入时，每一页都要正确处理，
并保留原有的懒分配逻辑及失败返回约定。

.. admonition:: 小心：写入时重新取得物理地址
   :class: mycaution

   COW 处理会把页表项指向新物理页。``copyout()`` 不能沿用处理前
   缓存的旧物理地址；跨页复制时还须对每个目标页分别检查权限与 COW 标记。

权限更新与地址转换缓存
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``fork()`` 清除父进程的写权限，以及 COW 处理改变物理页或恢复写权限后，
应在适当位置调用 ``sfence_vma()``，使修改后的页表生效。
否则 CPU 可能继续使用旧的地址转换或权限缓存。

2.5 测试与验收
--------------------------------------------------------------------------------

先用同一个 ``vmtest`` 重新观察 COW 的行为。重点比较全局变量所在页面：

.. list-table:: 普通 fork 与 COW fork 对照
   :header-rows: 1
   :widths: 34 33 33

   * - 阶段
     - 普通 fork
     - COW fork
   * - 子进程写入前
     - VA 相同、PA 不同。
     - 该页尚未被写入时，VA 相同、PA 相同。
   * - 子进程写入后
     - 在自己的原物理页上修改。
     - 共享页按需分离，写入方访问自己的副本。
   * - 父进程的变量值
     - 保持不变。
     - 保持不变。

**栈页可能在显式变量赋值之前就已经分离。** 函数调用和打印也会写栈，
不能仅凭“child before write”中的栈 PA 不同就判定 COW 失败。
若全局变量所在页还包含其他会被修改的数据，也应说明这些写入对观察结果的影响。

加入专项测试程序
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

下载课程提供的 :download:`cowtest.c <../downloads/lab5/cowtest.c>`，
放入工程的 ``user/cowtest.c``。本测试由课程配套提供，用于以下专项验证：

.. list-table:: cowtest 测试内容
   :header-rows: 1
   :widths: 30 70

   * - 测试项
     - 检查内容
   * - ``large-memory``
     - 实际写入约占配置物理内存 ``2/3`` 的区域后再 ``fork()``，
       验证共享物理页可以降低复制所需的内存。
   * - ``multi-generation``
     - 父、子、孙进程分别写入；多轮创建和退出后数据仍保持隔离。
   * - ``copyout-cross-page``
     - 子进程通过管道读取向跨页共享缓冲区写入，父进程原数据不变。
   * - ``reclaim``
     - 上述测试结束后再次执行大内存申请和 ``fork()``，
       检查明显的页面未回收问题。

大内存测试会实际触碰每个页面，避免只扩大虚拟地址范围而未分配物理页。
``reclaim`` 是回收回归测试，不能单凭它证明完全不存在任何小规模内存泄漏。

将 ``vmtest``、``cowtest`` 加入 ``Makefile`` 的 ``UPROGS``，
列表中已有的程序不要重复添加。以下条目放在列表中间，并保留末尾反斜杠：

.. code-block:: text
   :caption: Makefile 中的 UPROGS 列表条目

   $U/_vmtest\
   $U/_cowtest\

单核与多核运行
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

下面的编译命令在 **Linux 终端、xv6 工程根目录** 执行：

.. code-block:: bash

   make qemu CPUS=1

进入 xv6 后，在 **xv6 shell** 中依次运行：

.. code-block:: sh

   vmtest
   cowtest
   usertests -q

``vmtest`` 应显示地址转换正确、父子数据隔离；``cowtest`` 应包含：

.. code-block:: text

   large-memory: OK
   multi-generation: OK
   copyout-cross-page: OK
   reclaim: OK
   ALL COW TESTS PASSED

``usertests -q`` 应以 ``ALL TESTS PASSED`` 结束。

退出 QEMU：先按 ``Ctrl+A``，松开后再按 ``X``。回到 Linux 终端后执行：

.. code-block:: bash

   make qemu CPUS=3

在新启动的 xv6 中再次运行 ``vmtest``、``cowtest`` 和
``usertests -q``，检查多核并发下的引用管理。
学生发放的工程包含 ``usertests``，三个程序均为必做验收。
最终记录单核和多核结果，关闭临时调试打印，并确认第一部分的分配器测试仍然通过。

.. admonition:: 必做：完成验收并记录证据
   :class: mytodo

   #. 保存普通 ``fork()`` 与 COW ``fork()`` 的 ``vmtest`` 对照结果。
   #. 在 ``CPUS=1``、``CPUS=3`` 下分别通过 ``vmtest``、
      ``cowtest`` 和 ``usertests -q``。
   #. 说明大内存测试为什么能体现 COW 的作用，不能通过跳过测试、

   #. 确认第一部分的分配器接口与测试仍然可用，提交整合后的工程。

若出现 ``exec cowtest failed``，先检查 ``user/cowtest.c`` 是否存在、
``UPROGS`` 是否包含该程序，以及是否已重新编译启动。
``usertests`` 找不到时也应先检查它是否已构建并写入文件系统镜像。
``ls user/cowtest.c``、``rg`` 和 ``make`` 应在 Linux 终端执行，
不要在 xv6 shell 中执行这些源码检查命令。

2.6 实验报告与提交要求
--------------------------------------------------------------------------------

两部分合为 **一次 Lab5 作业**。在同一份报告中分别说明伙伴系统和 COW，
提交同一份整合后的 xv6 工程，不为第二部分另建分支或单独交一份工程。

报告应包含：

#. **实现说明**：列出修改的文件，用一张流程图或简短文字说明
   伙伴分配器、共享映射、引用计数、写缺页和 ``copyout()`` 如何衔接。
#. **地址对照**：选择一个变量，记录普通 ``fork()`` 和 COW ``fork()``
   的 VA、写入前后 PA 与父子变量值，解释何时共享、何时分离。
#. **测试证据**：提供页表打印、地址查询，以及单核和多核下
   ``vmtest``、``cowtest``、``usertests -q`` 的关键输出；
   保留第一部分的测试记录。
#. **问题分析**：说明一个实际调试问题或一个边界情况，
   例如分配失败、真正只读页被写入、最后一个引用消失。

在报告中回答以下问题：

* 父子进程访问同一 VA，为什么普通 ``fork()`` 的 PA 不同，而 COW ``fork()`` 在写入前可能相同？
* 为什么必须区分真正只读页和 COW 页？写缺页处理成功后为什么重试原指令？
* 用户态写缺页已处理，为什么 ``copyout()`` 仍需单独检查 COW？
* 进程退出时如何用引用计数决定是否回收物理页？引用数为 1 时可怎样避免复制？
